# 知识库综述（Overview）

当前知识库围绕一条主线：**在 AI 工作台里，用"可复用的方法包 + 结构化沉淀"把概念学习和知识管理做成可持续积累的系统**。最早六份源文档构成两个主题群，后续两次 ingest 各扩出一个：

## 主题群一：AI Agent 核心概念（四概念学习系列）

- [[Agent]]：把流程控制权交给大模型的系统——模型在循环里自己"想→做→看→再想"。判断 Agent 与工作流的关键是"谁决定下一步"。
- [[Context]]：模型每次决策能看到的全部信息（token 化、窗口有限）。它是 Agent 的"工作台"——窗口里信息的质量决定决策质量。
- [[Skill]]：把"某类任务怎么做"固化成文件（SKILL.md + 渐进式披露），随仓库分发复用。它是 Agent 跨越会话的"方法传承"。
- [[LLM]]：Agent 的决策大脑本体。靠 Transformer + 预训练 + 规模化涌现能力 + 对齐调优获得"能想会写"的能力；本身没有手脚，装进 Agent 才有行动。

四者关系（详见 [[sources/concept-relationship]]）：**Agent 是干活的人，上下文是他此刻的工作台，Skill 是他手边的作业指导书，LLM 是提供智力的大脑。** 上下文每轮是临时的，Skill 是持久的资产。

## 主题群二：自维护知识库方法（本库自身的实践）

- [[SelfMaintainingWiki]]：把"知识管理"本身做成一个 Agent 任务——喂入源文档，Agent 持续维护互链的结构化 wiki。
- [[LLMWikiAgent]]：这个范式的开源代表作，本知识库的目录结构、ingest 工作流、页面规范均借鉴其设计（MIT 协议）。

**贯穿全库的判断**：与其让 AI 每次从零开始，把"方法"（Skill）和"知识"（wiki）都沉淀成文件资产，让 AI 与人都能持续复用——这套思路同时解释了 [[Agent]] 时代的 PKM 实践与课程作业的设计逻辑。

## 主题群三：考研专业资料的事实核查（新增）

- [[sources/yunnan-mjc-334-440-past-papers]]：把一份图片型 PDF 的 14 套云大新传专硕真题转录为可复制的文字版，逐套与外部来源交叉比对，修正年份错误，并把缺失与存疑集中留白。
- [[YunnanUniversity]]：院校与学院定位，用来解释真题里国际传播、民族与乡村议题为何长期出现。
- [[syntheses/yunnan-mjc-kaoqing-analysis]]：题型演变、实务题构成、主题分布与备考判断。

**这一主题群的方法意义**：它是本库"防幻觉硬规则"的一次实际演练。凡是单一来源的说法标为待核，凡是原始材料与外部来源冲突的地方公开列出两方表述，凡是找不到的部分直接留白，不做填补式推断。

## 主题群四：多 Agent 团队（2026-10 新增）

- [[MultiAgentTeam]]：一个 lead 拆活、几个各带独立上下文的成员分头干、回来交压缩结论。它买的是上下文容量与并行度，代价约 15 倍 token。
- 判据收敛成一句：**读出并发，写入串行**。检索、核实、读文件可以并行；改文件、定规范、统一风格必须一个人做。
- [[sources/multi-agent-team]]：一手材料 8 条，含 [[Anthropic]] 的 Research 系统工程复盘（90.2% / 15 倍 token）与 [[Cognition]] 的两篇（2025-06 反对、2026-04 修正）。两派同周发布，看似矛盾，实际在描述"读多"与"写多"两类负载。
- [[WorkBuddy]]：产品侧的两种形态——Agent Teams（团队领导 + 成员 + 任务板 + 信箱）与 v2.154.0 起的自主组队（agent 自己拉人建频道）。

**这一主题群与前三群的关系**：[[Agent]] 讲单个实例怎么转起来，这一群讲多个实例怎么排班。两者共用同一个约束——[[Context]] 窗口有限，所以要么压缩进一个窗口，要么切开分给几个人。
