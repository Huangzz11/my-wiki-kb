# Hotspot Scout · 新传热点候选清单

每天早上扫一遍当天热点，筛出**值得做成新传案例分析**的议题，推一份候选清单给用户。
用户从清单里挑一个之后，再交给 `hotspot-case-card` 出图卡和归档。本 Skill **不产出图卡**。

## 触发

- 定时任务（每日 08:00）触发。
- 用户说「扫今天的可做热点」「推热点候选」「热点线索清单」「今天有什么值得做的传播学案例」。

## 第一步：抓取候选议题

**信源组合（两者都要用，缺一不可）**

1. **热榜层**——找到"今天大家在讨论什么"：
   - 微博热搜榜（`https://s.weibo.com/top/summary`）
   - 抖音热榜 / 今日头条热榜
   - 搜索时用 `WebSearch`，`freshness` 设为 `d1`
2. **媒体层**——回到主流媒体交叉核实，并提取争议焦点：
   - 光明网、澎湃新闻、极目新闻、红星评论、新京报评论、荆楚网东湖评论、四川网络广播电视台
   - 这一步同时完成"事实核查"，是候选清单质量的关键。

**注意**：热榜里的词条常常是同一个事件的多条热搜，先归并成事件再判断，不要按词条计数。

**同时记录破圈线索**（第二步首选标准要用）：扫榜时顺手记下同一事件出现在哪几个平台的榜单、是否被非垂类账号与主流媒体社会新闻版跟进、有没有被压成一句可传播的话。这些是「破圈度」的证据，事后翻稿很难补，扫的时候就要留。

## 第二步：筛选

### 2.1 首选标准：破圈度（2026-10-15 用户指定，排序权重最高）

同为合格候选时，**优先选破圈度高的**。判断"破圈"看四点：

- **跨平台**：话题是否同时在微博、抖音、小红书、新闻客户端等多个平台发酵。只在一个平台、一个垂类社区里热的，无论争议结构多完整，都排在同批候选的后位。
- **跨圈层**：讨论是否溢出原属圈层（饭圈、电竞圈、汽车圈、医学圈、法律圈）。只有行业内人士在讨论的，属圈层内热。
- **一般公众知晓度**：不关注该领域的人是否也听说了、能否一句话复述并参与讨论。能说出来的才叫破圈。
- **有可感符号或可模仿行为**：事件能否压成一个具体的、不依赖专业背景就能理解的东西——一个物件、一个动作、一句台词、一个数字。参照库内样板：编号 23「六十厘米的蛋挞」、编号 28「谁来了都得闪两步」均属此类。抽象的制度争议、只有从业者才关心的流程问题，破圈度天然低。

**破圈度与题材门槛不冲突**：破圈不等于娱乐化。热度极高的明星私事、体育赛果仍然按 2.2 排除项剔除；反过来，制度类议题如果是全民都在议的（如影响面覆盖多数家庭的收费、就业、教育问题），同样算高破圈度。

### 2.2 硬门槛（不合格的直接丢掉）

一个议题要进清单，必须**同时**满足：

- [ ] **公共事件类**：涉及公共规则、群体关系、媒介伦理、平台机制、消费文化、性别议题、代际关系等。
- [ ] **排除项**：纯娱乐八卦、明星私事、体育赛果、纯商业营销、无公共争议的灾难事故——一律剔除。
- [ ] **≥2 个独立媒体报道**作为支撑。只有一个来源的，不入选（可标注"单来源待核"后留作备选，但不出现在正式清单里）。
- [ ] **有可辨认的争议结构**：存在对立立场或制度张力。判断方法很直接——**能不能一句话写出双方各自的道理**？写不出来，说明理论套不上去，丢掉。
- [ ] **还没有被本库存过**：先读 `kb/新传热点事件解读/README.md` 的目录表，避开已收录事件及其后续同源事件（除非出现了独立的新争议点）。

## 第三步：为每个候选写五要素

每条控制在 **150 字以内**，用户要 1 分钟扫完。格式：

```markdown
### 候选 N｜<事件名，标题党写法，见下>

- **事件摘要**：<时间 + 地点/主体 + 发生了什么，2 句以内>
- **争议焦点**：<对立的两种立场各自是什么，1-2 句>
- **破圈度**：<跨平台与跨圈层的证据 + 一般公众能否参与 + 有无可感符号/可模仿行为，1-2 句>
- **理论方向**：<2-3 个具名理论，如"框架理论（恩特曼）/ 沉默的螺旋（诺依曼）">
- **来源**：<媒体名 + 链接，≥2 个>
- **推荐度**：★★★（最推荐）/ ★★ / ★
```

**推荐度怎么给**：以**破圈度为首要权重**，再叠加理论切口与争议结构。破圈度高（多平台共振、一般公众在议、有可感符号）＋争议结构清晰＋理论切口多的，给 ★★★；破圈度高但争议结构或信源偏弱的，★★；争议结构完整但只在单一平台或单一圈层内热的，最高只给 ★★。

四要素之外的**破圈度**一栏必须单独写，写清依据，不许只写"热度高"。

### 3.1 候选名要写成标题党（2026-10-15 用户指定，硬性）

候选名是用户第一眼看到的东西，写法与图卡标题一致（规范同时写在 `xiaohuang-hotspot-case/SKILL.md` 的「标题规范」）：

- **要**：谁＋做了什么＋结果如何，顶到最前；用具体数字（金额、时长、人数）；制造落差或悬念；说人话。
- **不要**：隐喻式标题（把事件压成一个比喻物，如「一张『撞脸』的脸」「一把随时能打开的钥匙」）、概念化冒号标题（`<意象>：<抽象判断>`）、AI 味套话（「当……成为……」「……的背后」「……的边界在哪里」「不只是 A，更是 B」）、学术黑话上标题、娱乐化词（反转／塌房／翻车／打脸）。
- **长度** 14—22 字，超出就把细节放进「事件摘要」。
- **硬约束**：标题党不等于造谣。可以藏原因、可以制造落差，不得改写事实、不得把推测写成结论；口径未确认的数字（两说的人数、金额）不准上标题。

对照示例：

| 旧（隐喻／概念化） | 新（标题党） |
|---|---|
| 一张「撞脸」的脸：网友拼出的寻亲剧本，落在了谁身上 | 工厂大叔撞脸陈小春被网友催认亲，拍视频的同事辞职了 |
| 一把随时能打开的钥匙：千万精装房空置数年被砸成毛坯 | 一千万给女儿买的嫁妆房，被陌生人砸成了毛坯 |
| 一百五十多款应用集体关上大门：AI 智能体与超级 App 的入口之争 | 豆包想替你点外卖，微信淘宝等 150 多款 App 集体说不 |

## 第四步：产出与存档

**数量：2-3 条。** 宁可 2 条高质量的，也不要 5 条凑数的。

1. 写文件 `kb/热点候选/YYYY-MM-DD.md`：

```markdown
---
title: "热点候选清单 YYYY-MM-DD"
type: hotspot-scout
date: YYYY-MM-DD
candidates: N
---

# 热点候选清单 · YYYY-MM-DD

> 由 hotspot-scout 自动生成。选中某条后说「做编号 N」，交 hotspot-case-card 出图卡。

<按格式列出各候选>

## 本期弃选记录

<列出扫到但因硬门槛被剔除的议题及一句话原因，如"某明星离婚：纯娱乐八卦，无公共争议结构">

## 待核项

<来源冲突或单来源的细节>
```

**弃选记录必须写**，它是判断筛选标准是否走偏的依据，也方便用户质疑标准。

2. 在对话中**直接呈现清单全文**（用户不打开文件也要能看到）。
3. **不提交 git，不推送仓库。** 每日清单由用户在需要时手动归档。

## 质量红线

- **不编造**。查不到来源的事件不写；来源冲突时两方表述都保留在「待核项」。
- **不为了凑数降低门槛**。当天没有合格素材时，直接说「今日无符合标准的候选」，并列出被剔除的议题及原因。**这不算失败，硬凑一期才是。**
- **破圈度必须写依据**。跨了哪几个平台、溢出了哪个圈层、一般公众在议什么、有没有可感符号，逐条写清；不许用「热度高」「全网热议」「讨论度很高」这类空话代替证据。
- **标题党只作用于「怎么说」，不改变「说什么」**。候选名与图卡标题一律说人话、给数字、做落差；不得用隐喻物替代事实，不得为了冲击力改写数字或把推测写成结论。
- 理论必须**具名**（学者或理论名），禁止写"这体现了传播学规律"这类空话。
- 禁止「不是……而是……」句式（含「并非…而是…」「不在于…而在于…」变体）。
- 事件回顾里涉及的车次、日期、人数等具体字段，**核实后再写**，这类字段最容易被转载者串位。
