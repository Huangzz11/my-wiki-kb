# Hotspot Scout · 新传热点候选清单

每天早上扫一遍当天热点，筛出**值得做成新传案例分析**的议题，推一份候选清单给用户。
用户从清单里挑一个之后，再交给 `hotspot-case-card` 出图卡和归档。本 Skill **不产出图卡**。

## 触发

- 定时任务（每日 08:00）触发。
- 用户说「扫今天的可做热点」「推热点候选」「热点线索清单」「今天有什么值得做的传播学案例」。

## 第一步：抓取候选议题

**信源组合（两者都要用，缺一不可）**

1. **热榜层**——找到"今天大家在讨论什么"：
   - 微博热搜榜（`https://s.weibo.com/top/summary`）
   - 抖音热榜 / 今日头条热榜
   - 搜索时用 `WebSearch`，`freshness` 设为 `d1`
2. **媒体层**——回到主流媒体交叉核实，并提取争议焦点：
   - 光明网、澎湃新闻、极目新闻、红星评论、新京报评论、荆楚网东湖评论、四川网络广播电视台
   - 这一步同时完成"事实核查"，是候选清单质量的关键。

**注意**：热榜里的词条常常是同一个事件的多条热搜，先归并成事件再判断，不要按词条计数。

## 第二步：筛选（硬门槛，不合格的直接丢掉）

一个议题要进清单，必须**同时**满足：

- [ ] **公共事件类**：涉及公共规则、群体关系、媒介伦理、平台机制、消费文化、性别议题、代际关系等。
- [ ] **排除项**：纯娱乐八卦、明星私事、体育赛果、纯商业营销、无公共争议的灾难事故——一律剔除。
- [ ] **≥2 个独立媒体报道**作为支撑。只有一个来源的，不入选（可标注"单来源待核"后留作备选，但不出现在正式清单里）。
- [ ] **有可辨认的争议结构**：存在对立立场或制度张力。判断方法很直接——**能不能一句话写出双方各自的道理**？写不出来，说明理论套不上去，丢掉。
- [ ] **还没有被本库存过**：先读 `kb/新传热点事件解读/README.md` 的目录表，避开已收录事件及其后续同源事件（除非出现了独立的新争议点）。

## 第三步：为每个候选写四要素

每条控制在 **150 字以内**，用户要 1 分钟扫完。格式：

```markdown
### 候选 N｜<事件名（一句话说清是什么）>

- **事件摘要**：<时间 + 地点/主体 + 发生了什么，2 句以内>
- **争议焦点**：<对立的两种立场各自是什么，1-2 句>
- **理论方向**：<2-3 个具名理论，如"框架理论（恩特曼）/ 沉默的螺旋（诺依曼）">
- **来源**：<媒体名 + 链接，≥2 个>
- **推荐度**：★★★（最推荐）/ ★★ / ★
```

**推荐度怎么给**：理论切口多、争议结构清晰、有同类事件可做"同源案例"的，给 ★★★。

## 第四步：产出与存档

**数量：2-3 条。** 宁可 2 条高质量的，也不要 5 条凑数的。

1. 写文件 `kb/热点候选/YYYY-MM-DD.md`：

```markdown
---
title: "热点候选清单 YYYY-MM-DD"
type: hotspot-scout
date: YYYY-MM-DD
candidates: N
---

# 热点候选清单 · YYYY-MM-DD

> 由 hotspot-scout 自动生成。选中某条后说「做编号 N」，交 hotspot-case-card 出图卡。

<按格式列出各候选>

## 本期弃选记录

<列出扫到但因硬门槛被剔除的议题及一句话原因，如"某明星离婚：纯娱乐八卦，无公共争议结构">

## 待核项

<来源冲突或单来源的细节>
```

**弃选记录必须写**，它是判断筛选标准是否走偏的依据，也方便用户质疑标准。

2. 在对话中**直接呈现清单全文**（用户不打开文件也要能看到）。
3. **不提交 git，不推送仓库。** 每日清单由用户在需要时手动归档。

## 质量红线

- **不编造**。查不到来源的事件不写；来源冲突时两方表述都保留在「待核项」。
- **不为了凑数降低门槛**。当天没有合格素材时，直接说「今日无符合标准的候选」，并列出被剔除的议题及原因。**这不算失败，硬凑一期才是。**
- 理论必须**具名**（学者或理论名），禁止写"这体现了传播学规律"这类空话。
- 禁止「不是……而是……」句式（含「并非…而是…」「不在于…而在于…」变体）。
- 事件回顾里涉及的车次、日期、人数等具体字段，**核实后再写**，这类字段最容易被转载者串位。

## 与其他 Skill 的分工

| Skill | 职责 |
|---|---|
| `topic-research` | 通用主题调研（多源检索、交叉验证），在本流程里承担信源检索与核查环节 |
| **`hotspot-scout`（本 Skill）** | 每日扫榜、筛选、出候选清单 |
| `hotspot-case-card` | 用户选定后：5 点理论解析 + 3 张 1080×1440 图卡 + 归档 `kb/新传热点事件解读/` |
| `wiki-keeper` | 维护 `kb/wiki/` 的互链页面（index/overview/log、概念页、双链） |
